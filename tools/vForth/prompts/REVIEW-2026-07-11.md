Revisione a posteriori dei tre commit di implementazione della giornata:
IM2-HW (1b196c5), DMA (057a548), PAINT (ae88ade). Esito: tutti e tre
contenevano bug gravi e nessuno era stato verificato a runtime. Le

## Causa comune: falso "hang" dell'emulatore

Durante la sessione PAINT l'emulatore headless sembrava bloccato al boot
e il codice e' stato committato senza verifica. In realta' NON c'era
nessun hang: il boot richiede ~113 secondi su questo Pi (~110k istr/s,
~12.5M istruzioni) e il timeout di default (2 minuti) del tool Bash
tagliava la corsa a un soffio dal prompt. Con un timeout adeguato
(>= 5 minuti) l'emulatore funziona perfettamente.

**Lezione di processo: mai committare codice Forth non verificato
nell'emulatore; per emu/repl.py usare sempre timeout >= 300s.**

## ae88ade - PAINT (Scanline Span Fill) - ROTTO, riscritto

Bug trovati nella prima stesura:

1. `>=` non esiste in vForth (ne' core ne' inc/): il file non compilava.
2. `PAINT-PUSH` in stack underflow: `2!` consumava tutto e il successivo
   `PAINT-SP !` restava senza argomenti. Il check di overflow confrontava
   un offset con un indirizzo (mai vero) e il ramo overflow lasciava un
   elemento orfano sullo stack.
3. `R@` attraverso DO...LOOP: in vForth `(DO)` mette indice e limite sul
   return stack, quindi dentro il loop `R@` = indice del loop (identico a
   `I`), NON il valore salvato con `>R` prima del DO. Tutto
   `(PAINT-FILL-SPAN)` era invalido; inoltre `R@ SWAP DO` passava
   (limit=y, start=x_right).
4. `ROT ROT` in PAINT con soli 2 elementi sullo stack -> underflow.
5. `HEX` attivo -> `1024 ALLOT` = $1024 = 4132 byte invece di 1 KB.
6. Assi confusi: bound $1FF applicato a x (verticale, max 192/256)
   anziche' a y (orizzontale, max 512). Vanno usati V-RANGE/H-RANGE.
7. Perso il check `?TERMINAL` (BREAK) presente nell'originale.

Riscrittura (stessa data): nessun R@ attraverso DO...LOOP (bounds dello
span in VARIABLE PAINT-Y1/PAINT-Y2, riga corrente tenuta sullo stack dati
con DUP I), PUSH/POP simmetrici su offset byte, seed-compression (un solo
seed per run libero della riga adiacente), BREAK svuota il seed stack,
wrapper BASE @ ... BASE !. Verificata su griglia mock nell'emulatore
headless (forma a U concava: entrambi i bracci riempiti, esterno intatto).

Refactoring correlato: PAINT estratto in `inc/PAINT.f`; sia
`lib/GRAPHICS.f` (monolitica) sia `lib/GRAPHICS-COMMON.f` (modulare) ora
fanno `NEEDS PAINT` al posto della copia inline (regola del lockstep).
`inc/PAINT.f` NON dichiara `NEEDS GRAPHICS`: nel percorso modulare
GRAPHICS non e' definita e il NEEDS avrebbe caricato l'intera libreria
monolitica dentro GRAPHICS-COMMON. Il file richiede che PLOT/POINT/EDGE
e V-RANGE/H-RANGE siano gia' definiti (lo sono in entrambi i percorsi al
punto del NEEDS PAINT); caricato su sistema nudo fallisce con "PLOT ?",
comportamento documentato nell'header.

## 057a548 - DMA - mai caricato con successo, CORRETTO (stessa data)

1. `VALUE DMA-A-ADDR` senza valore iniziale: in vForth VALUE e' un
   wrapper di CONSTANT con sintassi `n VALUE nome`. Cosi' com'e' consuma
   il `BASE @` salvato a inizio file (DMA-A-ADDR = 10), i VALUE successivi
   pescano spazzatura e il `BASE !` finale CORROMPE BASE.
2. `DMA-LEN !` / `DMA-B-ADDR !` / `DMA-A-ADDR !` scrivono usando il
   VALORE della costante come indirizzo -> scritture in memoria
   arbitraria. Servono VARIABLE (o TO ovunque, non il mix attuale).
3. `(DMA-WR0)` invia i parametri invertiti: con stack ( aAddr len ) i due
   DMA-W mandano prima len poi aAddr, ma il protocollo WR0 vuole A-address
   lo/hi seguito da length lo/hi. Manca uno SWAP.

Bug ulteriori trovati sistemando:

4. `NEEDS DMA` (usato dal tutorial 057) non poteva riuscire: la lib non
   definiva nessuna parola `DMA`. Aggiunta guard word `: DMA ;` in fondo
   al file (pattern di lib/INTERRUPTS.f: definita per ultima, cosi'
   NEEDS riesce solo a caricamento completo). NB: lib/AY.f ha lo stesso
   problema latente (nessuna parola `AY` per `NEEDS AY`) - da valutare.
5. Commenti con em-dash U+2014: violavano la regola 7-bit ASCII.
6. Tutorial 057: le aree di test erano $E000-$E37F, cioe' dentro la
   finestra MMU7 del dizionario heap - un DEMO su hardware reale
   avrebbe corrotto l'heap. Sostituite con buffer ALLOTati nel
   dizionario; sorgente riempita di $55 per la verifica con DUMP.

Fix applicati: VARIABLE al posto dei VALUE, SWAP in (DMA-WR0),
DMA-FILL senza TO, DMA-STATUS ora manda anche $A7 (INIT-READ-SEQ) tra
mask e lettura come da datasheet Z80 DMA, guard word, ASCII pulito.
Load-test in emulatore headless: la lib compila, BASE preservato,
stack bilanciato, DMA-FILL-BYTE riceve il byte.

Parti gia' corrette in origine: costanti WR0-WR6 coerenti col
protocollo Z80 DMA, DMA-W manda LSB per primo (verificato contro
`SPLIT ( n -- lo hi )`), DMA-DONE? col bit 5 attivo-basso.
Verifica dei trasferimenti reali solo su CSpect o hardware
(il DMA non e' emulato headless).

## 1b196c5 - IM2-HW - non compila, DA RIPROGETTARE

1. `DI` ed `EI` non esistono in nessun punto del progetto ->
   `IM2-HW-INIT` non compila. Prova che la lib non e' mai stata caricata.
2. `IM2-HW-TABLE` e' spazzatura: in
   `HERE $1F AND ?DUP IF 32 SWAP - ALLOT THEN CONSTANT IM2-HW-TABLE`
   l'ALLOT consuma il valore e CONSTANT prende cio' che capita sullo
   stack. Manca `HERE` prima di CONSTANT e mancano i `32 ALLOT` per
   riservare la tabella (le definizioni successive la sovrascrivono).
3. Gli xt Forth scritti crudi nella vector table IM2 non possono fare da
   ISR: la CPU salta all'indirizzo in tabella; una colon-definition
   (`call Enter_Ptr`) partirebbe senza salvare AF/BC/DE/HL (BC e' l'IP
   del programma interrotto!) e `: ISR-RET ;` termina con EXIT che
   deraglia tutto. Serve un trampolino CODE per slot: push registri ->
   esecuzione handler -> pop -> EI + RETI.
4. Bit dei registri sbagliati (dev guide r3, Interrupt Control/Enable):
   - $C4: ULA e' bit 0, non $80 (bit 7 = Expansion bus INT!).
     LINE = $02 (bit 1) e' corretto.
   - CTC0 sta su $C5 bit 0, non su $C4 $08 - incoerente con la stessa
     Phase 2 che mappa CTC1-7 su $C5 bit 1-7.
   - $C0: i 3 bit alti del LSB della tabella vanno AI BIT 7:5
     ("supplying the top 3 bits ... to bits 7-5"); il codice fa
     `5 RSHIFT` mettendoli nei bit 2:0. Corretto: `$E0 AND 1 OR`.
5. Minori: REG! ridefinito (e' gia' core); `[']` usato senza
   `NEEDS [']`; MARKER chiamato `IM2-HW` anziche' `NO-IM2-HW` (funziona
   per NEEDS ma devia dalla convenzione lib/).

La struttura dell'API (slot 0-13 secondo la priorita' hardware, shadow
mask per $C4/$C5/$C6) e' buona e va conservata nel redesign. Aggiornare
prima `prompts/IM2-HW-PLAN.md` con il trampolino, poi riscrivere.
