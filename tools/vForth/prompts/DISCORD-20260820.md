🚀 vForth 1.8 — builds 2026-08-17 and 2026-08-20 are out!

Two builds, one headline: **vForth has named local variables now.**

The core binary is unchanged in both (bar the build stamp) — LOCALS is a pure library. It patches nothing and redefines no core word, so `MARKER NO-LOCALS` unloads it cleanly and loading it can't disturb what you already compiled.

**Declared in place**
```forth
: MULADD  ( a b c -- n )  { A B C }  A B * C + ;
```
`{` is the first word of the body: it names the arguments in the order the caller pushed them and binds them. A local reads like a `VALUE` — and you write to it with `TO` (`12 TO A`).

**Output locals**
An optional `--` inside the braces marks a second group: not bound from the stack, created at 0 on every entry, and pushed automatically — in declaration order — by every exit path, the closing `;` and any early `EXIT` alike.
```forth
: SUM-TO  ( n -- sum )  { N -- ACC }  N 0 ?DO  ACC I 1+ + TO ACC  LOOP ;
```

**Re-entrant — RECURSE works**
A deliberate deviation from the Forth-2012 wordset: a local here is a permanent cell, not a frame slot. Re-entrancy comes from shallow binding — on entry each cell's previous content is saved on the return stack, and every exit path restores it — so two live activations of the same word each see their own values. Budget: 8 locals per scope, 4+4n bytes of return stack per activation (and that stack is 160 bytes).

The older two-part form still works, and is what `{` is built on:
```forth
3 LOCALS-FOR MULADD  A B C
: MULADD  LOCALS  A B * C + ;
```

**SEE reads it back**
Decompiling a word with locals used to hang. It now terminates and prints the binders by name — `SEE SQZ` on `: SQZ { U V } U V + ;` gives `V U LIT n >R U V + EXIT` — because each local carries a second, same-named header whose only job is to make the binding preamble legible.
